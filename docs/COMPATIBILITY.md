# 兼容性矩阵与报错处置手册

本文档回答两个问题：

1. **能跑在哪些 Windows 上**，各自需要什么前提；
2. 出错时**报的是哪一类错、为什么、怎么处置**——包括程序内的错误分类标识（用于诊断报告统计）。

> 说明：程序只依赖 Python 标准库，界面用的是 `tkinter`（Tk 8.6）。没有 C 扩展依赖，
> 所以"装不上某个包"这类问题不存在；剩下的兼容性风险集中在 **系统补丁、TLS 1.2、
> UCRT 运行库、文件路径长度** 这四块。

---

## 零、启动形态：目录版 vs 单文件（决定「能不能双击就开」）

常见症状，三条往往同时出现：

- 双击 exe 报错 / 一闪而过 / 干脆没反应；
- **必须右键「以管理员身份运行」才启动得了**；
- 每次启动都要干等好几秒。

根因是**单文件（onefile）形态**：它每次启动都会把自身解压到 `%TEMP%\_MEIxxxx`。
当 `%TEMP%` 不可写、被组策略限制、被安全软件拦住、或磁盘满时，解压失败 → 双击直接失败；
而「以管理员身份运行」换了一个完整性级别，恰好能过 —— 于是看起来像「这程序需要管理员权限」。

实际上：程序只读 `HKEY_CURRENT_USER`、只写你自己的用户目录（`%LOCALAPPDATA%`、桌面下载夹），
**任何形态都不需要管理员权限**，代码里也没有 `requireAdministrator` 清单。

| 形态 | 启动开销 | 依赖 `%TEMP%` 可写 | 无管理员可用 | 定位 |
| --- | --- | --- | --- | --- |
| **目录版（onedir）** | 不解压，通常 <1 秒 | 否 | 是 | **默认发布形态**，所有人都该用它 |
| 单文件（onefile） | 每次解压约 10 MB | 是 | 条件是 `%TEMP%` 可写 | 备选，只在「必须往 U 盘拷一个文件」时才用 |

另一个经常被误当成「报错」的东西是 **SmartScreen**：任何**没有代码签名**的 exe，第一次从网上下载后
双击都会弹「Windows 已保护你的电脑」。它不是病毒告警。点「更多信息」→「仍要运行」一次即可通过；
随包提供的 `首次使用-双击我.bat` 会解除这些文件的「来自网络」标记并建桌面快捷方式，之后不再弹。

## 一、操作系统支持矩阵

| 系统 | 状态 | 前提与注意事项 |
| --- | --- | --- |
| **Windows 7 SP1（64 位）** | 支持（需打补丁） | ① 必须是 **SP1 + 64 位**，32 位不提供支持；② 需要 **KB2533623**（或后继 KB3063858），否则打包后的程序启动即失败；③ 需要**通用 C 运行库 UCRT**（KB2999226 / KB3118401，或直接装 `vc_redist.x64.exe`）；④ 需要 **TLS 1.2**：装 KB3140245 并按微软说明打开 `WinHttp`/`Schannel` 的 TLS 1.2 开关，否则对 `https://www.mediafire.com` 的请求会在握手阶段失败；⑤ 打包时必须带上 **Tcl/Tk 8.6 的数据目录**（`tcl8.6`、`tk8.6`），否则运行时报 `Can't find a usable init.tcl`。 |
| **Windows 8.1（64 位）** | 支持 | 系统自带 UCRT 与 TLS 1.2，无需额外补丁。仍建议保持系统更新（根证书依赖系统更新）。 |
| **Windows 10（64 位）** | 主力支持 | 开发与日常验证都在此环境；21H2 / 22H2 实测可用。不需要任何附加运行库。 |
| **Windows 11（64 位）** | 支持 | 注意：**打包机若为 Win11，必须剔除随包携带的 `ucrtbase.dll`**（见下节），否则产物拿到 Win7 上会以 `GetDaylightFlag` 缺少入口点的方式崩溃。程序本身在 Win11 上运行无特殊要求。 |

### 打包侧的三个硬约束（与上表一一对应）

| 约束 | 具体做法 | 不做的后果 |
| --- | --- | --- |
| 解释器版本 | 固定 **Python 3.8**（3.9+ 官方不再支持 Win7） | Win7 上双击无反应或启动失败 |
| Tcl/Tk 数据 | `packaging/build.spec` 遍历 `<python>/tcl` 下的 `tcl8.6`、`tk8.6`（以及 `tcl8`），按运行时相对路径打进 `tcl/` | 启动即报 `Can't find a usable init.tcl` |
| UCRT 版本 | 打包后剔除 `ucrtbase.dll` 与 `api-ms-win-core-*.dll`，**保留** `api-ms-win-crt-*.dll` | 把 Win11 的 `ucrtbase.dll`（10.0.26100）带到 Win7（最高只支持 10.0.14393）会崩 |

> 依据：`packaging/build.spec` 的 `_trim_packaged_runtime()`，以及 PyInstaller issue #6621 记录的同型事故。

## 二、报错类型 → 现象 → 原因 → 处置

「程序内分类」这一列就是诊断报告与失败清单里使用的稳定标识（`mfd/failures.py` 的
`KIND_TEXT` 键），报 issue 时可以直接引用它。

### 2.1 网络与协议层

| 程序内分类 | 典型现象 | 常见原因 | 处置 |
| --- | --- | --- | --- |
| `http_403` **HTTP 403** | 解析正常、开始下载后立刻失败，日志写「MediaFire 返回 403：拒绝访问」 | ① **直链已过期**（直链带会话校验，长时间挂机后失效）；② 文件被分享者改成**私密**；③ 运营商 / 代理 / 防火墙**拦截**了 `download*.mediafire.com` | 先点「重试全部失败」（会重新解析、拿新直链）；仍失败则用浏览器打开该文件页确认是否还能匿名下载；换网络（关代理 / 换手机热点）再试 |
| `http_404` **HTTP 404** | 「文件或页面不存在（可能已被删除）」 | 上传者删除了文件、取消了分享，或链接本身拼错 | 重新解析文件夹拿最新清单；该条目从失败清单里删掉 |
| `http_429` **HTTP 429** | 下到一批文件的中间开始连续失败，提示「请求过于频繁」 | 并发太高 / 间隔太短，被 MediaFire 限流 | 线程数调到 **1**、下载间隔调到 **3 秒以上**，等 10 分钟再「重试全部失败」 |
| `tls` **SSL 证书错误** | 「SSL 握手失败（可能是系统缺少根证书或补丁不全）」 | 系统根证书过期、系统时间不对、Win7 未启用 TLS 1.2、或中间设备做了 TLS 拦截 | 校时 → 装根证书更新（Win7 装 KB3140245 并开启 TLS 1.2）→ 关掉会替换证书的安全软件/代理后重试 |
| `net_timeout` **连接超时** | 「网络超时：连接 MediaFire 超过 30 秒没有响应」 | 出口被墙 / 代理不通 / DNS 解析到不可达地址 | 先用浏览器确认能打开 mediafire.com；检查代理、换 DNS（8.8.8.8 / 223.5.5.5） |
| `net_timeout` **读取超时** | 解析到一半或下载中途停住；日志显示「MediaFire 在传数据的过程中停住了（已重试 3 次）」 | 走代理时接口响应慢、分块读取中途卡住 | 程序已自动重连重读 3 次（退避 2/4/8 秒）；仍失败就降线程数、换网络。注意断点文件会保留，重试即续传 |
| `net_reset` **连接重置** | 下载到某个百分比后固定失败，报「连接被对方重置」（Windows 10054） | 运营商 / 防火墙中途切断长连接；个别网络对境外大流量限速 | 线程数降到 **1**、间隔调大；换网络环境；重试会从断点续传，不会从头下 |
| `net_dns` **域名解析失败** | 一开始就失败，提示解析不到域名 | DNS 污染 / hosts 被改 / 本地 DNS 故障 | 换 DNS，检查 hosts 与代理的 DNS 模式 |
| `proxy` **代理认证 407** | 全部请求失败，报代理相关错误（407 / Proxy Authentication Required） | 系统代理需要用户名密码，但程序用的是 `urllib` 默认代理读取方式，不带认证凭据 | 关掉需要认证的代理直连；或改用不需要认证的代理；或在代理客户端里对本机放行 |
| `http_5xx` **服务器内部错误** | 间歇性失败，报 500/502/503 | MediaFire 服务端临时故障 | 等几分钟再「重试全部失败」 |

### 2.2 MediaFire 接口层

| 程序内分类 | 典型现象 | 常见原因 | 处置 |
| --- | --- | --- | --- |
| `api_error` **API 127** | 「MediaFire 接口返回错误：…（文件夹不存在或已被删除）」 | 文件夹被删 / key 拼错 | 重新复制分享链接 |
| `api_error` **API 128** | 「…（文件夹是私密的，需要登录才能访问）」 | 分享者把权限改成了私密 / 需要提取码 | 向分享者确认权限；本工具不支持带密码的分享 |
| `api_error` **API 129** | 「…（文件夹链接里的 key 无效或不是文件夹）」 | 把**单个文件的链接**当成文件夹链接粘贴；或 key 复制不全 | 直接粘原始分享链接即可——程序会自动识别 `?key` 短链接并在 129 时改按单文件处理；若链接明确写着 `/folder/` 却报 129，说明该 key 确实不是文件夹 |
| `link_missing` **解析不到直链** | 「页面里找不到下载按钮（MediaFire 可能改了页面结构）」 | MediaFire 改版、或页面要求密码 | 用浏览器打开该文件页确认；属于页面结构变化时请报 issue（附诊断报告） |
| `link_expired` **直链已失效** | 下载开始即 403 / 立即中断 | 直链有时效，长时间挂机后必然过期 | 直接重试（每次重试都会重新解析直链） |

### 2.3 本地文件系统

| 程序内分类 | 典型现象 | 常见原因 | 处置 |
| --- | --- | --- | --- |
| `filename` **文件名非法** | 极少数文件保存失败 | 文件名含 `\ / : * ? " < > \|`、控制字符、以点或空格结尾、或命中 `CON`/`PRN`/`COM1` 等保留名 | 程序在**下载前**就净化了文件名（非法字符换 `_`、保留名加后缀、单名截断到 180 字符），一般无需人工处理；仍失败请附上报错文件名 |
| `disk_full` **磁盘空间不足** | 「写入文件失败：…」（Windows 错误 112） | 目标盘满了 | 清盘或换下载目录后「重试全部失败」；断点文件 `.part` 会自动续传 |
| `path_too_long` **路径过长（260 字符）** | 保存阶段失败，报路径太长（Windows 错误 206） | 下载目录层级太深 + 文件名太长，总和超过 MAX_PATH | 程序已按 255 字符上限自动截断主名（保留扩展名），并把过长的目录判为不可用；仍失败就换一个浅目录（如 `D:\MF`） |
| `disk_perm` **权限不足** | 「无法创建目录 / 无法覆盖同名文件 / 拒绝访问」（错误 5、13） | 目标是 `C:\Program Files`、系统受控目录，或被安全软件锁定 | 换到用户可写目录（下载夹、D 盘自建目录）；不要把程序和数据放进 Program Files |
| `hash_mismatch` **SHA-256 校验不符** | 「文件校验不通过，已删除并会重新下载」 | 传输被中间设备改写、代理插入了错误内容、或源文件在下载期间被替换 | 程序会删掉坏文件并重下；反复出现请检查代理/杀软是否在改写 HTTPS 流量 |
| `size_mismatch` **文件大小不符** | 「下载不完整：已收到 X，应为 Y」 | 连接中途断开。程序允许 `max(4 KB, 1%)` 的容差，超出即判失败 | 重试即可续传；持续失败参照 `net_reset` 处置 |
| `canceled` **已取消** | 状态显示「已取消」 | 用户点了停止 | 不算失败；重新开始即从断点继续 |

### 2.4 启动阶段（只对打包出的 exe）

这一类发生在**界面还没出来之前**，所以日志页、失败清单、诊断报告里全都看不到，只能靠现象判断。

| 现象（按报错原文） | 常见原因 | 处置 |
| --- | --- | --- |
| 双击**毫无反应**；或黑框一闪即逝 | 单文件版启动时要先把自身解压到临时目录。`%TEMP%` 不可写（组策略把 TEMP 重定向到只读盘、临时目录被清空权限、磁盘满、漫游配置损坏）就会解压失败并直接退出 | 命令行执行 `echo %TEMP%` 看指向哪；确认该目录存在且能新建文件、所在盘有 200 MB 以上空余。不行就把 TEMP/TMP 临时改到 `D:\Temp` 再启动 |
| `INTERNAL ERROR: cannot create temporary directory!` | 同上，这是 PyInstaller 引导器的原文（控制台版能看到，界面版看不到） | 同上 |
| 杀毒软件弹「拦截了可疑的自解压程序」 | 单文件 exe 的工作方式就是自解压，启发式容易误判 | 把 exe 加入信任/排除；或改用源码运行（`pythonw run.pyw`），源码模式不解压 |
| 「Windows 已保护你的电脑」（SmartScreen） | exe 没有代码签名证书 | 点「更多信息」→「仍要运行」；或右键属性里解除锁定 |
| 报 `Can't find a usable init.tcl` | 打包时漏了 Tcl/Tk 数据目录 | 用仓库自带的 `packaging/build.spec` 重新打包，不要手写 spec |

> 本节三条的前因后果都记录在 `packaging/build.spec` 与 `run.pyw` 的注释里：程序**可以**在只读的 `%LOCALAPPDATA%` 下运行（数据目录会自动降级），但**不能**在不可写的 `%TEMP%` 下启动——因为解压是引导器的前置动作，程序代码还没开始执行。

## 三、怎么把这些信息交给维护者

1. 打开程序 → **「诊断」页** → 点 **「导出诊断报告」**，得到一份 JSON；
2. 报告里包含：系统与运行环境、失败条目的**「操作系统 × 报错类型」交叉统计**；
3. 一并附上「日志」页里 `ERROR` / `WARN` 前后的片段；
4. 文件名含隐私时可以把名字替换成 `<file>`，但**请保留分类标识与报错原文**——它们才是定位依据。

导出内容不会包含下载内容本身；失败清单里保存的路径只到文件名一级，用户主目录会被掩码成 `<用户主目录>`。
